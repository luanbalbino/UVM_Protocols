# Serial Peripheral Interface (SPI) – Overview

The **Serial Peripheral Interface (SPI)** is a synchronous, full-duplex serial communication protocol widely used to connect microcontrollers to peripherals such as sensors, memory devices, and displays.

---

## Key Features

- **Synchronous protocol** using a shared clock (`SCLK`)
- **Full-duplex** communication (simultaneous transmit and receive)
- **Master-slave** architecture (one master, one or more slaves)
- Simple hardware interface and efficient data exchange

---

## SPI Bus Signals

| Signal | Name                        | Direction         | Description                                   |
|--------|-----------------------------|-------------------|-----------------------------------------------|
| `MOSI` | Master Out, Slave In        | Master → Slave    | Transmits data from master to slave           |
| `MISO` | Master In, Slave Out        | Slave → Master    | Transmits data from slave to master           |
| `SCLK` | Serial Clock                | Master → All      | Clock signal generated by the master          |
| `SS`   | Slave Select (aka `CS`)     | Master → Slave(s) | Selects which slave is active during transfer |

---


## How It Works

1. **Master selects** a slave using the `CS` line.
2. **Master generates clock** via `SCLK`.
3. Data is simultaneously **shifted out** on `MOSI` and **read in** from `MISO`.
4. Communication continues as long as the `CS` line is active (low).


---

## Bit Order

The bit transmission order must be agreed upon:

- **MSB First** *(default)* – Most Significant Bit is sent first.
- **LSB First** – Least Significant Bit is sent first. -> *not implemented*

---

## ⚙️ SPI Clock Modes (CPOL and CPHA)

SPI defines 4 clocking modes based on two configuration bits:

- `CPOL`: Clock Polarity (idle state of `SCLK`)
- `CPHA`: Clock Phase (which edge to sample data on)

| Mode | CPOL | CPHA | Clock Idle | Sampling Edge | Change Edge |
|------|------|------|-------------|----------------|---------------|
| 0    | 0    | 0    | Low         | Rising         | Falling       |
| 1    | 0    | 1    | Low         | Falling        | Rising        |
| 2    | 1    | 0    | High        | Falling        | Rising        |
| 3    | 1    | 1    | High        | Rising         | Falling       |

> ℹ️ Clock mode must match on both master and slave for reliable communication.
